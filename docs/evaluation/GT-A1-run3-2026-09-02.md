## The gates I added this morning were themselves broken

Both defects passed unnoticed until deliberately falsified. This is the same failure the whole audit is about, one level up.

**F-7 · The coverage gate was inert.** It passed a **0.99** threshold at **71%** real coverage. Two causes, neither of which reports anything: `enableUnitTestCoverage` was never set, so AGP produced no data at all; and the exec path was wrong, so `executionData` was empty — and JaCoCo treats "no data" as "no violation". A silent pass is worse than no gate, because it manufactures confidence. **Lesson encoded:** raise the threshold to 0.99 and confirm the build fails before trusting the gate. A coverage gate that has never failed has never been shown to work.

**F-8 · The render check had both failure modes.**
- *False PASS:* it sampled the screen without checking which app was in front. The new app had crashed, the previous app was still foreground, and the check happily reported the previous app's correct palette.
- *False FAIL:* it used a fixed `sleep`. On this software-GPU emulator the first frame took ~20s (`Davey! 2088ms`, 88 skipped frames), so an 8s settle captured a 99.7%-uniform pre-paint frame and reported the palette as wrong.

**Lesson encoded:** assert the foreground package; poll the semantics tree for expected content instead of sleeping; and treat a near-uniform capture as a *capture* failure, never a render result.

## F-9 · `CanvasProgress()` crashed the app — and explains run 1's seam violations

`Progress.kt` passed `Float.NaN` to Compose's **determinate** `LinearProgressIndicator` whenever `progress` was null — the default. So the most obvious possible call, `CanvasProgress()`, threw `IllegalArgumentException: current must not be NaN` on composition and killed the app. It was unfixed on the branch being published to Maven Central.

This reframes run 1's finding F-3. canvas-commerce's `AccountScreen` imports **both** `CanvasProgress` and `CircularProgressIndicator`: the worker tried the Canvas component, hit this crash, and fell back to raw M3. At least 4 of the 5 raw-M3-widget violations were **workarounds for a crash in the design system**, not carelessness. Blaming the worker for the seam violation would have been wrong.

Fixed by branching on `progress == null` to select the correct overload.

## F-10 · `CanvasTheme` paints nothing

The theme supplies tokens and the M3 bridge but draws no background, and the corpus's `CanvasTheme { content() }` snippet never said a content root must establish the ground. A scaffold that follows the snippet literally shows the *platform* window background (`#FAFAFA`) — off-palette, with every gate green. Run 1's app only avoided this because its nav host happened to use a `Scaffold`, which paints `colorScheme.background`.

Encoded: wrap the nav host in `Box` + `background(tokens.color.bgSurface)` — Foundation, not an M3 `Surface`, so the app needs no Material3 dependency and the seam check stays clean.

## F-11 · ktlint and Compose cannot both pass without `.editorconfig`

`standard:function-naming` rejects PascalCase functions, which every `@Composable` is. A Compose project with ktlint blocking (§7) **cannot pass its own gate** until `.editorconfig` disables that rule. Run 3 hit it immediately with 4 violations on correct code. canvas-commerce had solved it months ago and the corpus never mentioned the file, so every scaffold rediscovers it. Now a Term.

## Friction the corpus should absorb

- **ink-basic component signatures are undiscoverable.** The corpus names `CanvasListItem`, `CanvasProgress` and friends but documents no parameters, and now that ink-basic is a binary artifact its source is not in the tree. I guessed `subtitle`; the real parameter is `supportingText`. Candidate: a component signature table in `presentation-impl.md`.
- **Two build-config mistakes cost a full cycle each**: the kotlinx-serialization converter's package moved to `retrofit2.converter.kotlinx.serialization`, and `by collectAsStateWithLifecycle()` needs an explicit `import androidx.compose.runtime.getValue`. Both are one-line, both cost a compile round-trip.

## Verdict

**0.57 → 0.86.** The corpus fixes worked: §5 went from the worst section to clean, §8 and §6 from fail/partial to pass. §3 and §7 remain partial for reasons that are recorded rather than accidental.

The uncomfortable part is F-7 and F-8: two of the four gates I added this morning were themselves broken, and both would have passed review. Only falsification caught them. The habit that matters is not writing gates — it is proving a gate fails when it should.
