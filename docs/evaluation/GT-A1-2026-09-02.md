# GT-A1 — first real run

> **Date:** 2026-09-02 · **System version:** 0.1.0 (`fix/corpus-and-grant-audit`, e2d3d67)
> **Subject:** `canvas-commerce` — FakeStore client, 93 Kotlin files, produced by CANVAS
> **Method:** golden-task exit criterion + bring-up on `emulator-5554` (API 34+), then scored per §.

The first time CANVAS output has been measured. Everything below is observed, not predicted.

## Exit criterion — PASS

`./gradlew assembleDebug testDebugUnitTest ktlintCheck detekt lint` → **BUILD SUCCESSFUL** (24s, 118 tasks).
Unit tests **26 passed / 0 failed** across 9 classes. detekt baseline holds **0** suppressions — the gate is not being gamed.
Bring-up: installed, launched, `topResumedActivity=com.example.canvas.debug/com.example.canvas.MainActivity`, no `AndroidRuntime` fatals.

**So the mechanical gates work.** Every finding below passed straight through them.

## F-1 · The app renders stock Material, not the palette (§5) — **fail**

Sampled from the running app: page background `#FEF7FF`, chip fill `#E8DEF8`. Those are Material 3 *baseline* `background` and `secondaryContainer`. ink-basic's light `bgSurface` is `#FBF9F7` — warm neutral. The shipped app is lavender.

`CanvasTheme` **is** applied at the root (`MainActivity.kt:23`), so this is not a missing theme. The cause is the **partial T2 bridge**: the vendored `CanvasTheme` mapped 9 M3 colour roles and left the rest at baseline, so every unmapped role — `background` first among them — renders stock.

This is precisely the failure palette's ADR-0001 was written to prevent ("structurally correct but visually bland"). It survived build, lint, ktlint and detekt without a murmur, because no mechanical gate can see it. **A screenshot found in one second what four gates could not.**

## F-2 · Vendoring broke the design-system seam (§5)

`vendor/ink-basic/` is a **hard copy** — no submodule, no `includeBuild`. CANVAS's README says the siblings are "referenced, never vendored"; `CONSUMING.md` documents a composite-build pathway. The scaffold ignored both and forked.

Consequence, measured: the fork still contains `Color(0xFFC00)` (`DefaultPalette.kt:113`) — the malformed ARGB literal that yields a **fully transparent** error colour in high-contrast mode. Fixed upstream in the sibling repo; invisible to this app. The app's own lint reports `InvalidColorHexValue` and the build passes anyway, because lint warnings do not block.

**The swappability the whole three-repo architecture exists to provide is not actually wired.**

## F-3 · The self-check gate did not run, and truncation predicts the damage (§5)

`presentation-impl.md` → `## ink-basic self-check` declared `<!-- 6 -->` against a 21-line section. An agent using that count as a `Read` limit sees rule 1 and stops. Violations in the produced app:

| Rule | Visible in a 6-line read? | Violations |
|---|---|---|
| 1 — raw M3 widget | **yes** | **5** |
| 2 — raw hex colour | truncated | 0 |
| 3 — raw `dp` where a token exists | truncated | **26** |
| 4 — bare `MaterialTheme.*` | truncated | **24** |

Rules that survived truncation: 5 violations. Rules cut off: 50. Rule 1 is also the most conspicuous, so this is correlation rather than proof — but it is the shape the truncation predicts, and the count was wrong. (Fixed in 59207b2; `scripts/selfcheck.py` now blocks it in CI.)

## F-4 · Navigation: the corpus contradicts the Quality Bar, and the build follows the corpus (§1)

QUALITY-BAR §1 mandates **Navigation 3**. The app ships `navigation-compose 2.8.5` with `NavHost` + `composable<HomeRoute>` — Navigation Compose 2.x type-safe.

That is not the worker inventing something: `navigation-impl.md` *claims* Navigation 3 in its header while every code sample in it is Nav Compose 2.x. The worker followed the code, as it should. **The doc's prose and its own examples disagree, and the Quality Bar agrees with neither.** Resolve the doc, then the app.

## F-5 · Two gates are unmeasurable as configured (§6, §3)

- **§6** demands ≥75% coverage on new code. **JaCoCo is not wired.** 26 tests pass; what they cover is unknown. A floor nobody measures is not a floor.
- **§3** demands a spec-first *generated* client and "no hand-written DTOs". There are **4 hand-written DTO files** and no generator task. The contract discipline was dropped silently.

## F-6 · Not under version control (§8) — **fail**

`canvas-commerce` has no `.git`. §8 requires trunk-based development, Conventional Commits and CI quality gates; none are possible. The scaffold reference prescribes the project skeleton but never initializes a repository.

## The lesson

CANVAS's three mechanical gates — build, tests, audit-by-grep — passed a build that ships the wrong colours, a forked design system, an invisible error state, a contradicted navigation mandate and an unmeasured coverage floor. **Every gate CANVAS owns is textual; every finding above is either visual or structural.**

The corpus was written ahead of use, against this repo's own "extract, don't predict" rule. This run is the first evidence, and it says the predictions were substantially wrong in the places nothing could check them.

# GT-A1 · re-run after the fixes (same day)

The findings above were closed and the same app re-measured, to test the fixes against running output rather than asserting them.

## What changed

`vendor/ink-basic` (the hard-copy fork) was deleted. `canvas-commerce` now consumes **`com.cesartista.canvas:ink-basic:0.1.0`** as a published artifact — the pathway `project-scaffold-impl.md` → `## Theme & Design Tokens` mandates. Resolved from `mavenLocal` because the Central coordinate is not live yet (verified 404 at `repo1.maven.org` on this date); the sibling repo publishes it with `publishToMavenLocal`.

## F-1 · closed — verified by measurement

| | before | after |
|---|---|---|
| sampled page background | `#FEF7FF` (M3 baseline) | **`#FBF9F7`** |
| chip fill | `#E8DEF8` (M3 `secondaryContainer`) | warm neutral |
| render check | **fail** | **PASS** |

Build successful, installs, launches, no fatals, and the app now renders the palette it was always supposed to. The causal chain is confirmed end to end: ADR-0001's "T2 must be total, not partial" → the completed bridge in ink-basic → published artifact → consumed by coordinate → correct pixels on screen.

**The render gate works.** It failed the broken build and passes the fixed one, on a defect no textual gate detected in either direction.

## F-2 · closed
The fork is gone; the seam is a real dependency edge. Swapping the palette is now a version bump rather than a manual re-copy.

## Still open on this app

- **F-3** (seam violations: 5 raw M3 widgets, 26 raw `dp`, 24 bare `MaterialTheme.*`), **F-5** (no JaCoCo, 4 hand-written DTOs) and **F-6** (no git repository) are unfixed *in canvas-commerce*. The corpus that produces such apps was corrected (9f5bb5c, 32f6d9c); this app predates the fix and was not regenerated.
- The emulator has no outbound network, so the product list is empty in both runs. That is the environment, not the app — no `UnknownHost`/timeout surfaced in logcat.

## Method note

Editing `settings.gradle.kts` here briefly removed `include(":app")` and broke the build. Because the project **has no git repository** (F-6), there was no undo — the fix had to be reconstructed by hand. F-6 stopped being theoretical about fifteen minutes after it was written down.
